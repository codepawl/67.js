# Changelog

## 0.16.0

- Draw the `foliage`, `mountain-valley` and grand valley reference frames without wind (issue #191). The reference harness left the renderer's default `wind: 0.3` on, which moved leaf cards by up to about four pixels at the reference camera while Blender drew them still. `foliage` falls from 0.0979 to 0.0838 against Cycles (EEVEE 0.0924), `mountain-valley` from 0.1769 to 0.1691, the three grand valleys by 0.0018 to 0.0077; no other scene moves. The README has the card-by-card comparison with Blender.
- Turn the floor sky trace (issue #197) on by default in the recipe path for a closed room a sun lights, at strength 0.2: `createAgentScene` calls `applyDefaultFloorSky(parts, environment)` from a lazily loaded module, loaded when the recipe names its sun (`keyColor` or `keyIntensity`). Open scenes and rooms lit by lamps alone are left as they are, because the trace made those worse against Cycles. `environment.floorSkyTrace: false` opts out, any other value leaves it on (documented in `docs/agent-look.md`). `applyFloorSkyVisibility` gains `onlyClosedRooms`, a lower default strength with it, and `report.meanVisibility`. FLIP against Cycles: `temple-hall` -0.0023, the three grand temple options -0.0051 to -0.0096, `dark-shaft` +0.0017, no other scene past 0.002. The README has the numbers.
- Add `applyFloorSkyVisibility` (`67js/addons/floor-sky-visibility`, issue #197), an opt-in trace of the sky each floor texel sees: 64 cosine-weighted rays per texel against the other parts, written into the floor's `skyVisibility`, which the shader already multiplies into the world and sky light. It adds nothing to the core entry, is off unless called, and leaves closed rooms alone unless `includeClosedRooms` is set. On the reference suite it improves 5 scenes by 0.004 to 0.010 FLIP (`car-paint`, `material-spheres`, `brushed-film`, `brick-flat`, `brick-graph`) and the three grand temple options by 0.011 to 0.021, but `long-street` gets worse by 0.0135 and three more scenes pass 0.002, so it is not on by default. The trace takes 0.5 to 1.7 s and the cut floor adds 0.1 to 0.3 ms per frame. The README has the numbers.
- Regenerate every cell of `baseline.json` and `grand.json` with the 8-bit EEVEE scorer (closes #258). Only the EEVEE columns and `cpu-vs-cycles` of `long-street` and `megacity-dusk` moved in `baseline.json`; the grand 67js columns moved a lot because the old file predated work on main. See `bench/reference/README.md`.
- Scale large glTF texture sets down at load instead of throwing (closes #260). When the images together pass `maxTexturePixels`, the largest are halved together until they fit, so 40 maps of 1024 px load with default options as 512 px. `asset.scaledTextures` lists each scaled image as `{ name, from, to }` and `asset.warnings` summarises it. The new `maxTextureImagePixels` option (default 16,777,216) is the hard ceiling for one image, which is still rejected before decoding. KTX2 images are never scaled.
- Raise the light limits to 16 point lights, 8 spot lights and 7 area lights (issue #261), from 8, 8 and 4. A server hall lit by 12 point and 7 area lights renders with every light visible. On an RTX 3060 at 960x540 each point light adds about 0.04 to 0.05 ms and each area light about 0.04 ms (16 point and 7 area lights: 1.92 ms, none: 1.07 ms; `bench/lighting/frame-time.mjs`). The light bake takes the same limits, the area limit is 7 so that the sun and all lights fit the 32 bit light-linking mask, and `material.lightMask` now defaults to `-1` (every bit) instead of `0x1fffff`.
- Document light intensity units and the three.js conversion (issue #262). `docs/agent-look.md` states the unit of the key, point, spot and area light intensities with a conversion table from three.js r155 and later, and `tests/light-units.test.js` ports one light of each kind with the table and checks the irradiance within 2 percent.
- Fit the default fog to the scene size (issue #263). A scene that sets no `fogDensity` now gets 0.006, or 1.2 divided by the scene diagonal when that is smaller, so a 900 m scene keeps 30 percent of its contrast at the far side instead of 0.4 percent. Scenes up to about 200 m are unchanged. `normalizeAgentLook` now returns `fogDensity: null` for "fit to the scene"; set a number, or 0 for none, to override.
- Warn when the shadow view and the light direction disagree (issue #264). A renderer whose `shadowBounds.eye` points 10 degrees or more away from `environment.lightDirection` now lists a `shadow-light-direction-mismatch` warning in `renderer.diagnostics`. `docs/agent-look.md` says the eye wins.
- Report a skipped ambient occlusion pass (issue #266). A frame with `effects.ambientOcclusion` above 0 on a renderer built without `depth: true` now sets a named `ambient-occlusion-without-depth` warning in `renderer.diagnostics`, which the preview's render info includes, instead of skipping the pass silently.
- Load glTF textures that use `EXT_texture_webp` (closes #274). The WebP source decodes like PNG and JPEG, counts toward the texture budgets from its header size, and falls back to the PNG or JPEG `source` when the browser cannot decode WebP.
- Load glTF files whose `COLOR_0` is RGBA with alpha below one (closes #278). The RGB colours are kept, the alpha is dropped, and `warnings` names the meshes where that happened.
- Load glTF files that use optional extensions and line primitives instead of refusing them (closes #280). An optional extension 67js does not read, such as `EXT_texture_avif`, is ignored and named in `warnings`; one in `extensionsRequired` is still refused. POINTS, LINES, LINE_LOOP and LINE_STRIP primitives are skipped with a warning that names the mesh. `KHR_materials_unlit` loads as the `unlit` material tag, and `KHR_lights_punctual` comes back as `asset.lights`: point and spot lights and the first directional light as `Renderer67` environment options. Not done: drawing the skipped primitives, and a reference-image check of a Khronos lights sample.
- Move the skin and morph shader code and the renderer's skin and morph validation, texture layout and packing out of the core renderer bundle (part of #281). `skinning.js` and `morph.js` register them on import, and every module that makes a pose (`createSkinPose`, `createMorphPose`, the glTF loader, rigs, retargeting, the crowd addon) imports them, so a lit box without a skin or morph target no longer carries them. Breaking: a renderer given a part with `skin` or `morph` that never imported those modules now throws and names the module to import. The post pass explosion step (the film's ignition scene) moved to `explosion-shader.js`, which the film player imports; a frame with `volumeExplosion` needs it. `scene:lit-box` is now 49,934 bytes gzip, under the goal of 50,000.
- Move the water, foliage, grass, terrain, moss, fire and smoke shading out of the core renderer bundle into `addons/world-material-shader` (part of #281). Breaking: a renderer that draws a part with one of those tags needs `import '@codepawlhq/67js/addons/world-material-shader'`; the terrain, vegetation, grass, clutter, film and agent terrain modules import it themselves, and a recipe loads it with `loadAgentSceneModules`. The environment map shading text now sits with the map builder, and GLSL line comments are stripped from the published bundles. The shader registry lives in the small `shader-registry.js`, so an addon that registers code no longer pulls in the renderer's shader text (`entry:spume` 25,410 to 12,411 gzip).
- Move the liquid and foam pass and the splat ground material out of the core renderer bundle (part of #281). Breaking: a renderer that draws a transmissive, `liquid` or `foam` part needs `import '@codepawlhq/67js/addons/liquid-shader'`, and one that draws `material.layers` needs `import '@codepawlhq/67js/addons/splat-shader'`; recipes and glTF files with transmission load the liquid code on their own, and the Spume player imports it. The environment map builder loads with `createEnvironmentMap`, so a renderer without an environment map no longer carries it. Measured by `npm run size`, gzip: `scene:lit-box` 66,497 to 56,343, `scene:gltf-box` 90,790 to 80,866, `scene:agent-scene` 110,277 to 103,794. The liquid program also compiles on the first liquid part instead of at start. `npm run size` now prints each goal scene against its goal.
- Match Blender 5.2's AgX in `environment.viewTransform: 'agx'` (issue #282). Grey 0.18 now maps to 0.460 sRGB against Blender's 0.461 (it was 0.501), and the colour ramp is within 0.0247 at most, 0.0026 on average (it was 0.0885 and 0.0252). The curve is a fit of Blender's AgX LUT: a per-channel sigmoid and two matrices. FLIP against Cycles AgX, `outdoor-hdri` 0.0997 to 0.0425, `material-spheres` 0.1467 to 0.0903, `character` 0.1238 to 0.0581.
- Score the view transforms against Blender 5.2.2 (issue #282): `npm run reference -- --view-transform agx --scene <id>,<id>` draws 67js with `viewTransform` and Cycles with Blender's AgX, and scores them into `bench/reference/view-transform.json`. The colour ramp shows `neutral` within 0.0079 of Blender (mean 0.0013) and `agx` within 0.0885 (mean 0.0252); the README has the table and the scene scores.
Add `environment.viewTransform` (`aces`, `agx`, `neutral`) and `.cube` or named looks in the renderer, the recipe and the path tracer, checked against Blender 5.2 on a colour ramp (closes #282, except the two scored reference scenes).
- The GPU path tracer traces the material `subsurface` block (issue #283 follow-up, part of #302): the same bounded random walk as the CPU tracer, compiled into the kernel only for a scene with a part whose weight is above 0, with the block in its own two-texel-per-material table. A scene without one compiles and renders the kernel it always did. Scored against the Cycles render of `subsurface`, see `docs/path-tracer.md`.
- Add a material `subsurface` block for skin, wax and leaves (part of #283): `weight` (0 to 1), `radius` (red, green, blue mean free path in units of `scale`, default `[1, 0.2, 0.1]`), `scale` (metres, default 0.05) and an optional `color`, named as Blender's Principled BSDF Subsurface Weight, Radius and Scale. Recipes and the MCP `scene_create` schema accept it with bounded numbers. The rasterizer widens the sun's diffuse past the shadow edge per channel and lets light through thin parts by the thickness the sun shadow map gives; the code is a lazily loaded addon (`@codepawlhq/67js/addons/subsurface-shader`, loaded by a recipe on its own) that compiles in only when a part has a weight above 0, so a scene without it draws the same picture and pays nothing. The path tracer does not read the block yet. `bench/reference/render-blender.py` exports it as Random Walk subsurface, and the reference scenes `subsurface` and `subsurface-off` score it against Cycles.
- Raise the subsurface addon back-face translucency from 0.5 to 1.0 (part of #283) so thin parts such as leaves pass more light, measured on the `subsurface` reference scene against Cycles; scenes without a subsurface weight draw the same picture.
- The path tracer traces the `subsurface` block (part of #283): a bounded Random Walk for parts with a weight above 0 (mean free path radius times scale, colour mapped to a single scattering albedo, at most 32 scattering events, exit back to the surface) and thin translucency for a card with nothing behind it. A weight of 0 draws exactly the pictures it drew before. Against the Cycles render with subsurface on, the `subsurface` scene scores 0.0795 with weight 1 and 0.0875 with weight 0 at 64 samples; the GPU tracer still ignores the block.
- Trace emissive maps and homogeneous volume fog in the path tracer, and name what it still skips (issue #284). An `emissiveMap` is read at each hit and scaled by `emission` and `emissiveColor`; `environment.volumeFog` is a uniform medium with exact free-flight sampling, lit by every light and the sky with shadow rays. `metrics.pathTracer.ignored` in an image job result now also lists anisotropy, iridescence, sheen, moss, splat layers and baked light maps. The new `emissive-sign` reference scene scores 0.0800 (the rasterizer scores 0.2372) against Cycles with the path tracer, and `fog` goes from 0.5333 to 0.0312 (the rasterizer scores 0.2021).

- Add outlines, toon light and polylines (part of #285). `environment.lines: {}` draws outlines of fixed pixel width at silhouettes, part boundaries, creases and depth jumps from the object ID, normal and depth guides. `lines.polylines` draws screen-width lines in the world, and `toon` on a material (or `lines.toon`) bands the light. - Add the `overshoot-lift-plain` task and a `--backend cpu|gpu` option to the agent modeling suite (issue #286). Three live Sonnet runs of each overshoot task passed with 2 tool calls each, because the agent never chose a named easing.
- Add named easing curves and `cubic-bezier` to keyframes (closes #286). A `LINEAR` or `SMOOTH` keyframe takes `easing` (`linear`, `cubic-bezier(x1, y1, x2, y2)` or `ease<In|Out|InOut>` + Sine, Quad, Cubic, Quart, Quint, Expo, Circ, Back, Bounce or Elastic) for the segment after it, with arguments for Back and Elastic, such as `easeOutBack(3)` and `easeOutElastic(1.5, 0.4)`. Recipe motion tracks, camera paths and material tracks take it, an unknown name throws an error that lists the valid forms, GLB export bakes eased tracks to linear samples, and every curve matches Blender 5.2 within 1e-4 (`tests/easing.test.js`). New suite task `overshoot-lift`; the Keyframes row of the parity ledger is updated.
- Keep the single 2048 x 2048 sun shadow map at one texel when cascades are on and nothing else reads it (issue #287). With `shadowCascades`, the main shader and the underwater lookup read the cascade array, so the single map was drawn and held for nothing: 16 MB of depth and one more shadow pass per caster change. It is still allocated and drawn when volume fog is on or a material has `subsurface`, the two places that read it. A cascaded scene at 960 by 540 allocates 77.66 MB of render targets instead of 93.66 MB (20 of 26 reference scenes drop 16 MB; the 6 with volume fog or subsurface keep the map), and 52 reference draws (26 scenes with and without 3 cascades) are byte-identical PNGs to `main`. The map also follows the casters now: a renderer that starts with nothing to cast and gets casters from `replaceParts` allocates the full map instead of keeping one texel.
- Add the opt-in addon `useCompactColor(renderer)` (`@codepawlhq/67js/addons/compact-color`, issue #287). It stores the frame and its multisample colour in 4 bytes a pixel (R11F_G11F_B10F) instead of 8: at 1920 x 1080 with 4 samples the render targets go from 110.92 to 71.37 MB. It has no alpha, so it needs `hdr: true` and an opaque canvas and throws otherwise, and it throws when the device lacks the renderer's sample count in that format. Mean FLIP against the default over the 26 reference scenes is 0.002 to 0.030 (median 0.021). Without the call the core keeps RGBA16F and draws byte-identical pictures.
- Draw the multisampled depth with 16 bits when the renderer has no depth texture (issue #287). A plain lit scene at 960 by 540 with 4 samples allocates 41.36 MB of render targets instead of 45.31 MB (`instanced-objects`), and the 25 reference scenes draw the same pictures (worst FLIP against the previous 67js picture 0.0000). A renderer with `depth: true` keeps 24 bits, because its resolve needs the same format. Two other steps failed the 0.002 FLIP limit and are not in: a 16-bit sun shadow map (brick scenes 0.0023 and 0.0031) and an R11G11B10F colour target (0.002 to 0.034 over the 25 scenes, about 0.02 on most). A 1024 shadow map changed `subsurface` by 0.006.
- Draw 3D Gaussian splats as an optional addon, `67js/addons/gaussian-splats` (issue #288). It reads a standard 3DGS PLY with a byte and splat count limit (512 MiB and 2,000,000 by default, 4,000,000 at most), and draws the splats after the opaque parts with the depth test against them, no depth write and a CPU counting sort, back to front, through a wrap of `drawBlendBatches` that needs no renderer change. The core bundle is unchanged. `docs/gaussian-splats.md` has the guide and `bench/gaussian-splats/README.md` the frame time and memory at 100,000 and 1,000,000 splats and the comparison with the three.js `GaussianSplat`. A part whose material still holds the values that passed the checks skips them, and the morph pass runs only when a morph or skin is in the update. 25,000 matrix-only parts take about 5 to 8 ms of JavaScript, from 33 to 55 ms (`npm run benchmark:update-parts`).
- Encode video frames in the page with WebCodecs (issue #301). `scripts/render-media.mjs` and the MCP video job draw a frame, hand the canvas to the browser's hardware H.264 `VideoEncoder` in the same task, and send only the encoded chunks (5 to 60 kB a frame) to Node over one binary WebSocket, where `ffmpeg -c copy` muxes them with the audio. The full 4,488 frame film at 1280 by 720 on the RTX 3060 took 20.6 s in all, 2.2 ms a frame of capture and 2.0 ms of draw, against 139.6 s for screenshots (25.1 ms a frame of capture) and 405.1 s for reading raw pixels over a WebSocket (84.8 ms a frame, 94 ms in a 10 s clip). Profiling showed ffmpeg was not the cost (3.7 ms a frame) and `readPixels` was 6.6 ms, but Chrome moved the 3.7 MB frame to Node at only 100 to 140 MB a second. The output matches the previous NVENC path at 44.8 dB PSNR and is tagged BT.709 limited range. `--capture auto` is the default for video and falls back to screenshots when the browser cannot hardware encode, or for `--encoder cpu` and `--backend cpu`. `--capture webcodecs` fails instead of falling back, `--capture raw` keeps the `readPixels` path as opt in, and PNG stills are unchanged. `npm run smoke:capture-parity` checks a decoded raw frame against its PNG seek. `ws` is a new dev dependency, bundled into the MCP server.
- The light bake can trace on the GPU (issue #302): `bakeLightmapsAsync(parts, lighting, { backend: 'gpu' })` starts a cosine weighted path at every covered texel in the GPU path tracer's kernel (a texel mode of the same shader, so lights, materials, maps and the bounce rules are the tracer's) and resolves with the same `{ parts, report }`; `report.backend`, `report.gpu` and `report.gpuCompileSeconds` say what ran. `backend` is `cpu` (the default and the reference) or `gpu`, as for the path tracer; the synchronous `bakeLightmaps` refuses `gpu` and names the addon. It lives in its own addon, `67js/addons/light-bake-gpu`, so the CPU bake and the core bundle do not carry it. It needs WebGL2 with float targets, does not take light linking (`affects`) or a sky-only bake, and `bench/reference/bake-compare.mjs` measures it against the CPU bake.
- Add a GPU backend to the path tracer, `backend: 'gpu'` (issue #302): the same algorithm and random numbers in a WebGL2 fragment shader, with the BVH, materials, maps, lights and sky in float textures, inside the path-tracer addon only. The 1920 by 1080 demo room at 64 samples took 58.2 s against 585.9 s on the CPU tracer, and GPU against CPU FLIP was 0.0001 to 0.0018 on the 16 reference scenes. `docs/webgpu-decision.md` records WebGL2 over WebGPU for this offline work.
- The GPU path tracer remeasured on the 1920 by 1080 demo room at 64 samples (issue #302): 38.7 s for a first compile of an unseen kernel text and 41.0 s again, 7 s of each compiling, so the under-60-s box holds with a cold shader cache. The light bake box stays open.
- Add `settings.renderer.denoise: "oidn"` for path traced render jobs (issue #303): Intel Open Image Denoise from the optional package `@codepawlhq/67js-denoise-oidn`, outside the core archive. `denoise` also takes `"wavelet"` (the old `true`) and `"none"`; `oidn` defaults to 16 samples, and a job without the package or its binary falls back to the wavelet filter and says so in `metrics.pathTracer.denoiserNote`. At 1920 by 1080 the denoise step took 1.6 s against about 9 s for the wavelet filter (measured). `bench/reference/denoise-*.mjs` compare the denoisers.

A KTX2 loader that transcodes to BC7, BC1, BC3, ASTC 4x4 or ETC2 is now accepted, and the renderer uploads each mip with `compressedTexSubImage2D`, so a 2K map takes about a quarter of the memory of RGBA8. The new `ktx2WorkerConfigFor(context)` export gives the loader the formats a context takes, and it falls back to RGBA8 where there are none. `asset.textureFormats` lists the format, size and bytes of each texture, and compressed KTX2 images count a quarter of their pixels toward `maxTexturePixels`.

On the depth-precision bench (GPU) the 500 m, 0.1 mm gap pair falls from 0.134 to 0.069 wrong pixels and the 500 m, 1 mm pair from 0.015 to 0.014; the rest of the 0.069 is the float32 step of the model's own vertices at that distance, which no vertex transform removes.

- Add reversed-Z depth as an addon (part of #310): `installReversedDepth(renderer, mode)` in `src/reversed-depth.js` draws the colour pass with depth 1 at the near plane, a 32-bit float depth buffer and `GREATER` where `EXT_clip_control` exists, and leaves the shadow maps, backgrounds and post passes on the standard range. `mode` is `true`, `false` or `'auto'`, which switches it on when a frame's far / near passes 10,000 or the coplanar check (`installDepthPrecision`, which also installs the warning) finds a flush pair more than 40 units from the eye. - A terrain that does not set `mirrorLevels` now builds its coarse water-mirror meshes (up to two halvings the resolution allows) when `applyWaterReflection` finds a water surface in the scene, so an agent needs no flag (part of #316). The levels are built from the heights the terrain already keeps. A terrain in a scene without water builds none of them, and an explicit `mirrorLevels`, 0 included, is kept as given. On the 900 m benchmark terrain the one-time build takes about 130 ms inside `applyWaterReflection`, adds 22 MB of mesh data, and leaves terrain without water at its old memory and build time. With no `mirrorLevels` in the benchmark call the mirror frame costs +25% over reflection off (8.08 against 6.45 ms, 240 samples per variant, RTX 3060), and the picture is pixel for pixel the one made with `mirrorLevels: 2`. The first frame after attaching takes 5.7 ms of GPU time, a normal frame.
- `scripts/benchmark-water-reflection.mjs` leaves `mirrorLevels` unset unless `--mirror-levels N` is given, and reports the `applyWaterReflection` time, the mirror mesh size and the first frame after attach (part of #316).
- The water mirror draw now skips a part whose bounding sphere covers under 5 pixels of radius on screen (it was 1.5), since the ripples and blur hide it (part of #316). On the 960 by 540 water benchmark (20k pebbles, dense terrain with `mirrorLevels: 2`) the mirror pass draws 97 instances and 184 K triangles where it drew 1,241 and 527 K; against the uncut mirror the lit frame differs by at most 3 of 255 per channel (mean 0.0017).
- `scripts/benchmark-water-reflection.mjs` builds its terrain with `mirrorLevels: 2` by default (`--mirror-levels 0` gives the old numbers) and runs its variants in turn for several rounds (`--rounds`, default 3) and pools the timings, so a machine under load drifts the same way for every variant (part of #316).
- Median GPU ms per frame on the RTX 3060 through the GPU lock, 960 by 540, 240 samples per variant: reflection off 6.08, old unculled mirror 10.79 (+77%), new mirror 7.60 (+25%), `updateEvery: 2` 6.54 (+7%), still camera 6.08 (0 mirror draws). With `mirrorLevels` left at 0 the new mirror costs about +70% in the same scene, because the mirror then draws every terrain triangle: a terrain used with water should set `mirrorLevels: 2`. With the mirror draw stripped to two instances the pass costs 0.1 ms, so the rest is the geometry it draws, not fill: a mirror at scale 0.5 is no faster than at 0.75.

Their chunk edges keep every finest-grid vertex, so they meet a neighbour's finest edge or another mirror mesh with no crack (a plain coarse mesh left gaps of up to 3 m on a hilly test terrain). `attachWaterReflection` hides these levels from every other draw and lets the mirror pick them by its own screen error, so a terrain that sets `mirrorLevels` must be used with it. No renderer code changed.
- Make the water reflection cheaper (part of #316): the mirror draw skips parts under the plane and sub-pixel parts, takes coarser levels, drops local lights and the cascade redraw, keeps its picture while the frame and parts are unchanged, and `attachWaterReflection` takes `updateEvery` for films.

On a 960 by 540 canvas the mirror draws 1,241 instances and 1.67 M triangles where the uncut mirror drew 7,321 and 3.50 M; the picture differs by at most 1 of 255 per channel.

## 0.11.0

- Add `67js/addons/grass`: terrain-following grass fields of clumped, curved blades with rounded normals, root-to-tip colour, dry patches, masks for paths, four presets and tile level of detail
- Bend `grass` tag vertices by blade height and roll wind gusts across the field as a travelling wave
- Break up grass fields with `patchiness` (short, thin and dense patches), seed `stalks` and folded blades, and let sunlight glow through backlit blades
- Add `67js/addons/clutter`: pebbles, chipped rocks with moss, twigs and fallen leaves scattered over terrain in streamed tiles, with four presets
- Share one tile and level-of-detail system between grass and clutter
- Add a `moss` layer to standard materials: its own rough, sheened, light-wrapping material with a sharp shading mask and a blurred cushion mask; clutter rocks use it
- Add splat `parallax` (default 0.03 m) for near-ground relief from the layer height maps
- Add splat `variation` (brightness and hue drift at three scales that grows with distance) and `edgeNoise` (ragged layer borders), both on by default
- Add `uv_unwrap` as a mesh edit and stack node: seams from an edge rule, automatic cuts until each island is a disk, least-squares conformal maps, axis charts for closed or stretched islands, area-even scaling and shelf packing into 0..1, with a report of islands, flipped triangles, area distortion and utilization
- Teach the `build-67js-scene` skill mesh modeling: a workflow, face and edge rules, tested recipes (crate, pillar, drum, bracket, bench row, planter, soap) and an error table; a test builds every recipe in the reference and requires a clean lint
- Shrink the MCP server bundle from 1,072 KB to 590 KB by keeping the scene engine out of it: capabilities and default limits now come from plain-data modules (`agent-scene-capabilities.js`, `mesh-operations.js`), and the MCP build fails if engine code returns; the npm archive drops from 1,003 KB to 887 KB
- Add `67js/addons/mesh`, a polygon mesh core for agent modeling: compact `MeshData` with attributes on point, edge, face and corner domains, a half-edge `EditMesh` with typed-array disk and radial cycles, `validateTopology`, conversion from renderer geometry with welding, quads and axis face tags, hard-edge corner normals, n-gon triangulation, render extraction and `lintMesh`
- Add semantic face selection and mesh edits (extrude region and individual, inset region and individual, delete, flip normals, translate with proportional falloff, merge by distance, tag) that tag the faces they create
- Add the recipe geometry type `mesh` (a base shape plus a replayable edit log) and the `mesh_edit` MCP tool, which appends or replaces edits atomically and reports each edit's result
- Add `loop_cut`: edge rings across quads picked by an edge rule (including `along` a direction), evenly spaced cuts or one cut at a factor, band tags, T-junction-free neighbours and interpolated UVs; and `alongNormals` for `extrude_face_region`, which extrudes rings and curved bands as one joined region
- Add edge `bevel` as a mesh edit and stack node: rim, angle, region-border or all-edge selection, width, segments, profile and overlap clamping, with sliding corners and smooth triangular patches where three rounded edges meet
- Add mesh booleans (union, difference, intersect) through Manifold WebAssembly as the `boolean` edit with an inline primitive cutter, tag transfer and polygon rebuilding; `manifold-3d` is an optional peer dependency, which the MCP runtime serves to its preview page when installed
- Add mirror, array and solidify as mesh edits and as a non-destructive modifier stack evaluated after the edits, with every prefix cached, and the `mesh_stack` MCP tool to set the stack or apply its first nodes into the edit log
- Report hollow cavities as valid in `lintMesh` instead of as inverted parts
- Add the `mesh_inspect` MCP tool: polygon counts, face sizes, parts, face tags, bounds and lint problems with suggested fixes for every recipe geometry

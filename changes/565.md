- Load and animate glTF files with duplicate or missing node names (issues #565 and #551). The decoder made names unique with a `_N` suffix but could still hand a later node the name it had just generated, so two channels collided and createAnimationClip threw "Each target property can have only one track"; it now skips taken suffixes. Unnamed nodes were named by a random uuid in clip tracks and by an empty string in the asset's node metadata, so a skinned file such as Khronos BrainStem threw "no clip track names a joint of this rig"; both now use the source id (`node-4`). Scale keys of exactly 0 are accepted (zero hides a node; negative still throws), and a skin whose joint has zero scale loads with that joint collapsed (and the existing warning) instead of throwing a singular joint transform error. `createRigFromSkin` no longer crashes on a singular inverse bind matrix.

- entry:view-transform-shader: a catalog .cube look is looked up by name in the renderer's look resolver (164 bytes gzip), so a recipe's look can be a shipped or catalog .cube file.
- scene:agent-scene+lazy: HDRI and .cube catalog entries add the name lists, the registry, two validated fields (hdri, look) and a capabilities entry (about 640 bytes gzip); the decoding runs in the preview page, not in the recipe code.
- goal:agent-scene: about 100 KB of shipped files in assets/looks (four files: two 128 x 64 HDRIs, two 9-point looks) sit outside every bundle; a bigger HDRI comes from the asset catalog.
- tool-total: the new hdri field and the wider look field in the one shared environment schema (343 bytes), the only MCP surface for catalog HDRIs and .cube looks.
- tool:scene_create: the hdri field and the wider look field (343 bytes), with names listed as an enum so an agent cannot guess a path.
- result:scene_capabilities: the catalogLooks entry lists the shipped HDRI and look names (308 bytes), so an agent finds them without a call to the docs.
